# BOUNCE BACK / 坦克竞技场

Godot 4.7.2 的 3D 坦克竞技场原型，不需要外部素材或插件。包含低多边形坦克、立体掩体、无实时光照材质和跟随相机。

## 运行

在 Godot 项目管理器点击「导入」，选择本目录的 `project.godot`，打开后按 **F6 或 F5** 运行主场景/项目。

主菜单选择「单人挑战」与电脑对战，使用全屏跟随相机；或选择「本地双人」同键盘对战，左屏跟随蓝方 P1，右屏跟随红方 P2。两个视角共享同一张地图与实时战斗状态。双人指同一台电脑，不支持联网。

## 对局设置

主菜单、结算和 Esc 暂停菜单都有两个选项，双方共用，切换模式或重赛会保留本次运行中的选择。暂停时修改对当前对局立即生效。

- **射击方式**：默认原版模式，按住开火可连续射击，玩家间隔 0.42 秒。选择手速模式后，每次按下开火键发射一发，没有冷却，按住或系统按键重复不会连发；P1 也支持鼠标左键点射（原版模式可按住左键连射）。AI 始终保留 0.7 秒开火间隔。
- **子弹反弹**：默认最多反弹 3 次，存在 4 秒。选择无限后，金属墙、边界和护盾反弹不限次数，子弹不会因时间到而消失，但击中坦克或砖墙仍会消失，重开对局也会清空。改回有限模式后，已超时的弹会消失，已用完反弹次数的弹在下次反弹时消失。

全场炮弹上限固定为 **50 发**，玩家双方和 AI 合计共用。达到上限时暂停生成新炮弹，已有炮弹不受影响；有炮弹被销毁后即可继续开火。手速模式需要再次按下开火键。HUD 显示当前数量，满额时变为黄色。无限反弹次数设置仍有效。

| 操作 | 蓝方 P1 | 红方 P2 |
| --- | --- | --- |
| 前进 / 倒车 | W / S | ↑ / ↓ |
| 向左 / 向右旋转 | A / D | ← / → |
| 开炮 | 空格 | Enter |
| 反弹护盾 | Q | / |
| 暂停/继续 | Esc | Esc |

采用坦克式操控：前进和倒车始终沿车身轴线，左右键连续旋转车身，支持 360° 任意朝向、原地转向以及边开边转。倒车速度低于前进速度；倒车时左右键仍对应车头向左/向右旋转。炮管与车身同步，沿当前车头方向射击。每辆坦克 3 点装甲，击毁对手得 1 分；先得 5 分获胜。120 秒到时比较得分，相同则平局。被击毁后在出生点复活，获得 2 秒保护。双人键盘可能有多键冲突，可以错开开炮时机。

坦克使用圆形街机碰撞体与墙体、边界和对方坦克碰撞。斜着撞墙会沿接触面滑动，贴墙仍可原地转向和倒车；每次移动也会修正已有重叠位置，避免持续卡住。

棕色砖墙一炮击碎；蓝色金属墙和地图边界反弹炮弹，单发最多反弹 3 次。自己的反弹炮弹也会伤害自己。护盾持续 0.8 秒、冷却 5 秒，能反弹敌方炮弹并改变归属。护盾状态和重生保护以坦克外围透明球罩显示。上方条形指示器显示护盾冷却。

当前战斗发生在平坦地面上，炮弹沿水平方向运动。相机从车身后上方跟随，转向时平滑跟转；重生时立即跟到出生点。

AI 通过网格寻路追击玩家，使用同样的连续转向与前进规则，瞄准玩家后开火，并在附近有敌方炮弹时尝试开启护盾。

## 文件

- `main.tscn`：主场景。
- `scripts/arena_3d.gd`：3D 模型与地图、共享世界、独立相机、左右分屏和 3D HUD。
- `scripts/arena.gd`：复用的对战规则、菜单、移动、AI、炮弹与合成音效，以及保留的 2D 绘制实现。
- `project.godot`：窗口和兼容性渲染配置。

## 自动验证

`Godot.exe --headless --path . -- --smoke-test`

验证双方真实按键绑定、原地旋转、倒车、边走边转、任意角度开火、撞墙停止、砖墙破坏、金属墙反弹、护盾归属、击毁计分、AI 移动、结算和重开，并验证 3D 共享世界、双相机、左右分屏和单人全屏布局。也建议两人实际试玩，调整移动速度、射速和护盾冷却。

图形回归检查：`Godot.exe --path . -- --render-test`。使用真实渲染器依次切换双人、单人、双人，验证启用视口的画面不是纯色，并将截图保存到 `.test-artifacts/`。此检查不能使用 `--headless`。

## 性能

重复箱体按材质合批，炮弹和火花使用可扩容的 MultiMesh；炮弹上限为 50，装饰火花上限为 256。所有材质使用无光照模式，移除实时灯光、阴影和 MSAA 抗锯齿，降低双人分屏渲染负担。坦克、炮弹和跟随相机在显示帧之间插值，战斗逻辑仍以固定 60 Hz 运行。右上方显示实时 FPS（启动第一秒内尚未稳定）及炮弹数量。碰撞只查询相邻网格，接触时修正位置并保留沿墙方向的移动。

性能对比命令：`Godot.exe --path . -- --benchmark`。此测试关闭垂直同步，暂停战斗逻辑，测量双人分屏静态渲染的空场景和 256 发炮弹场景，不能等同于整局游戏的帧率。

此前合批优化的一次对比（尚未移除灯光、未加 50 发上限）：空场景平均帧耗时从 2.420 ms 降至 1.695 ms；256 发炮弹从 7.338 ms 降至 2.002 ms，对应每帧绘制调用从 3626 降至 834。日志分别在 `benchmark-before.log`、`benchmark-after.log`。后台程序和机器状态会影响结果。性能工具直接注入的 256 发是渲染压力测试，正常开火不会超过 50 发。试玩请只保留一个运行中的游戏窗口。
